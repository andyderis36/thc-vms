## 3. FILE KONFIGURASI DOCKER COMPOSE

File `docker-compose.yml` disiapkan di root proyek untuk mempermudah orkestrasi:

```yaml
services:
  postgres:
    image: postgres:18-alpine
    container_name: thc-vms-postgres
    restart: always
    environment:
      POSTGRES_USER: thc_user
      POSTGRES_PASSWORD: thc_password_local
      POSTGRES_DB: thc_vms_db
    ports:
      - "5432:5432"
    volumes:
      - pgdata_local:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U thc_user -d thc_vms_db"]
      interval: 5s
      timeout: 5s
      retries: 5

  minio:
    image: minio/minio:latest
    container_name: thc-vms-minio
    restart: always
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    ports:
      - "9000:9000"
      - "9001:9001"
    volumes:
      - miniodata_local:/data

  minio-init:
    image: minio/mc:latest
    container_name: thc-vms-minio-init
    restart: "no"
    depends_on:
      - minio
    entrypoint: >
      /bin/sh -c "
      /usr/bin/mc alias set localminio http://minio:9000 minioadmin minioadmin;
      /usr/bin/mc mb localminio/thc-vms-bucket --ignore-existing;
      exit 0;
      "

volumes:
  pgdata_local:
  miniodata_local:
```

> **Catatan bucket privat**: `minio-init` hanya membuat bucket `thc-vms-bucket`
> bila belum ada — bucket **tetap privat** (tanpa perintah `mc anonymous`).
> Backend melayani berkas lewat presigned URL ber-TTL (`S3_PRESIGN_TTL_MINUTES`,
> default 15 menit), jadi jangan pernah membuka bucket untuk unduh anonim.

## 5. URUTAN MENJALANKAN SISTEM (*STEP-BY-STEP RUNBOOK*)

### Langkah 1: Jalankan Database & Object Storage
```bash
docker compose up -d
```
*Tunggu beberapa detik hingga PostgreSQL siap dan bucket `thc-vms-bucket` terbuat otomatis oleh container `minio-init`.*

### Langkah 2: Jalankan Migrasi Skema Database
Dari direktori `backend/`:
```bash
# Menjalankan seluruh script SQL up
migrate -path migrations -database "postgres://thc_user:thc_password_local@localhost:5432/thc_vms_db?sslmode=disable" up
```
*Atau, backend Go Clean Architecture dapat mengeksekusi migrasi otomatis saat startup pada mode `APP_ENV=local`.*

### Langkah 3: Eksekusi Database Seeder
Dari direktori `backend/`:
```bash
go run seeds/main.go
```
*Perintah ini akan memasukkan akun master, daftar lokasi cabang/POP, dan tujuan kunjungan ke PostgreSQL.*

### Langkah 4: Backfill Notifikasi Persisted (one-off, idempotent)
Dari direktori `backend/`:
```bash
go run cmd/backfill-notifications/main.go
```
*Memproyeksikan riwayat kunjungan yang sudah ada ke tabel `notification` (migrasi 000008) agar muncul di feed tiap penerima. Aman dijalankan berulang kali — setiap insert memakai `ON CONFLICT DO NOTHING`, jadi tidak menggandakan notifikasi. Cukup sekali setelah seeder.*

### Langkah 5: Jalankan Backend Server
Dari direktori `backend/`:
```bash
go run cmd/server/main.go
```
*API siap melayani request di `http://localhost:8080/api/v1/health`.*

### Langkah 6: Jalankan Frontend Next.js
Dari direktori `frontend/`:
```bash
npm install # atau pnpm install
npm run dev # atau pnpm dev
```
*Aplikasi web dapat diakses melalui browser di `http://localhost:3210`.*

> **Catatan Port Frontend**: Next.js di lingkungan lokal ini memakai port **3210**, bukan default 3000, karena ada `netsh portproxy` rule (IP Helper) yang mengikat `0.0.0.0:3000` secara permanen di mesin ini. Port tersebut di-pin di `frontend/package.json` (`next dev -p 3210`), jadi `npm run dev` selalu konsisten. Backend mengizinkan origin `http://localhost:3210` (lihat `backend/internal/delivery/http/middleware/cors.go`) — **ubah keduanya bila port FE diganti**, jika tidak semua request API akan diblokir CORS di browser.

### Langkah 7: Jalankan E2E Playwright (opsional)

Dari **root repo** (bukan dari `frontend/`):

```cmd
e2e.cmd                :: local headed (default)
e2e.cmd check          :: cek backend :8080 + frontend :3210 saja
e2e.cmd live           :: production headed, wajib ketik LIVE
e2e.cmd live-check     :: cek production via GET /health saja, tanpa menulis data
e2e-live.cmd           :: shortcut double-click untuk mode live
```

- `e2e.cmd` memakai Playwright lokal di `frontend/node_modules` (bukan MCP). Bila stack lokal mati, script menyalakannya lewat `vms.ps1` (`docker` → `be` → `fe`) lalu menunggu health check.
- Mode local **selalu** mengeset ulang `E2E_BASE_URL`/`E2E_API_BASE_URL` ke localhost dan menghapus override live dari shell sebelumnya, sehingga tidak mungkin tidak sengaja menembak production.
- Mode live hanya berjalan setelah preflight `GET https://vms.thckalbar.com/api/v1/health` sukses **dan** operator mengetik `LIVE`. Suite ini destruktif: membuat/menghapus kunjungan dan akun sementara di production.
- Login live dipacing `13000` ms karena rate limit production `5/menit/IP`; bisa dioverride dengan `E2E_LIVE_PACING_MS` bila perlu. Project `setup` dilewati (`--no-deps`).
- `E2E_SKIP_STORAGE_CLEANUP=1` dipaksa di mode live karena MinIO production internal. Objek `pending-*` yang diunggah suite **tidak** terhapus dari bucket; pembersihan harus dilakukan dari VPS.
- Report HTML: `frontend/playwright-report/index.html`. Jendela `e2e.cmd`/`e2e-live.cmd` tidak langsung tertutup (`pause`) agar hasil bisa dibaca.

## 8. DEMO TUNNEL GANDA UNTUK BACA BERKAS (FE :3210 + BE :8080)

Untuk demo remote (`vms-tunnel` / `vms share`), dua tunnel Cloudflare diteruskan: satu untuk FE (default port **3210**) dan satu untuk BE (port **8080**). Selama share, `NEXT_PUBLIC_API_BASE_URL` di `.env.local` frontend ditulis ulang ke URL tunnel BE (`<url-tunnel-be>/api/v1`), dan dikembalikan ke `http://localhost:8080/api/v1` saat share berhenti. Bila browser memblokir request, tambahkan origin tunnel FE ke `CORS_ALLOWED_ORIGINS` backend.

Bacaan berkas (`GET /api/v1/visits/{id}/file`) lewat host API yang sama sehingga selamat melewati tunnel: tidak ada host MinIO (`localhost:9000`) atau parameter presigned `X-Amz-*` yang bocor ke browser, jadi pratinjau SPK/KTP/selfie tetap terbuka lewat URL tunnel.

## 9. RUNBOOK TTL STAGING `pending/` (ILM SEBAGAI BACKSTOP, OPS-RUN, TANPA KODE)

Keputusan D2: tidak ada kode ILM di `EnsureBucket` (YAGNI). Reaper Wave-2 adalah alat presisi (24 jam, hapus objek `pending/` yang kedaluwarsa secara eksak); ILM MinIO/S3 di sini hanya jaring pengaman (*defense-in-depth*, misal 7 hari) bila reaper sempat mati. Direktori kategori persis dari `backend/internal/infrastructure/storage/object_key.go` (`categoryDirectories`): `assignment_letters`, `id_cards`, `checkin_photos`, `profile_photos`. Staging pending selalu berbentuk `<direktori>/pending/` — jangan mengarang prefix lain.

### 9.1 Setup alias `mc` (sekali saja)

```bash
# Lokal (dari host; di dalam docker-net ganti localhost dengan http://minio:9000)
mc alias set localminio http://localhost:9000 minioadmin minioadmin

# Produksi (isi dari .env VPS, jangan commit)
mc alias set prodminio https://<minio-prod-host>:9000 <PROD_ACCESS_KEY> <PROD_SECRET_KEY>
```

### 9.2 Terapkan aturan expiry — 4 prefix `pending/` SAJA (contoh 7 hari)

```bash
mc ilm add --expiry-days 7 --prefix "assignment_letters/pending/" localminio/thc-vms-bucket
mc ilm add --expiry-days 7 --prefix "id_cards/pending/"           localminio/thc-vms-bucket
mc ilm add --expiry-days 7 --prefix "checkin_photos/pending/"     localminio/thc-vms-bucket
mc ilm add --expiry-days 7 --prefix "profile_photos/pending/"     localminio/thc-vms-bucket
```

Produksi: ulangi 4 baris yang sama dengan `prodminio/<bucket-prod>` (nama bucket ikut `S3_BUCKET_NAME` di `.env` VPS). Prefix wajib diakhiri garis miring (`pending/`), tanpa itu aturan melebar ke key lain.

### 9.3 Verifikasi

```bash
mc ilm ls localminio/thc-vms-bucket
# Harus tampil TEPAT 4 aturan, semuanya berakhiran /pending/ — tidak ada aturan tanpa prefix /pending/.
```

### 9.4 Rollback (hapus aturan)

```bash
mc ilm rm --prefix "assignment_letters/pending/" localminio/thc-vms-bucket
mc ilm rm --prefix "id_cards/pending/"           localminio/thc-vms-bucket
mc ilm rm --prefix "checkin_photos/pending/"     localminio/thc-vms-bucket
mc ilm rm --prefix "profile_photos/pending/"     localminio/thc-vms-bucket
mc ilm ls localminio/thc-vms-bucket   # harus kosong / tanpa aturan pending/
```

### 9.5 Larangan

- **NEVER** menargetkan key non-`pending/`: jangan membuat aturan tanpa `--prefix`, atau berprefix `assignment_letters/`, `id_cards/`, `checkin_photos/`, `profile_photos/` polos — itu akan menghapus berkas final yang sah.
- **FORBID** aturan `AbortIncompleteMultipartUpload`: MinIO mengabaikannya; multipart tak lengkap sudah ditangani server lewat `stale_uploads_expiry`. Jangan menambahkan aturan sejenis dalam bentuk apa pun.
