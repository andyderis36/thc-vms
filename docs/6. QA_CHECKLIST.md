# SKENARIO UJI & QA CHECKLIST (QA_CHECKLIST.md)
# Project: THC Visitor Management System (VMS) - ISP Edition
# Versi: 3.1.0 (September 2026 LTS Tech Stack)

Dokumen ini adalah matriks pengujian jaminan kualitas (*Quality Assurance Checklist*) untuk memvalidasi kepatuhan fungsionalitas, keamanan data multi-cabang (*branch data scoping*), toleransi waktu check-in, dan integrasi object storage pada THC-VMS.

---

## 1. MATRIKS PENGUJIAN OTENTIKASI & ISOLASI CABANG (RBAC)

| ID Uji | Modul / Fitur | Peran Pengguna | Langkah Pengujian | Hasil yang Diharapkan | Kategori |
|---|---|---|---|---|---|
| **AUTH-01** | Login Berhasil | Semua Role | Masukkan email & password terdaftar yang valid | Berhasil login, menerima token JWT (HTTP 200), diarahkan ke dashboard sesuai role | Positif |
| **AUTH-02** | Login Gagal (Kredensial Salah) | Semua Role | Masukkan email valid dengan password salah | Menolak login (HTTP 401 Unauthorized), pesan error "Kredensial tidak valid" | Negatif |
| **AUTH-03** | Isolasi Cabang Admin | `admin` (Kantor Pusat Pontianak) | Mengakses endpoint `GET /api/v1/visits` | Hanya mengembalikan daftar kunjungan berstatus `location_id` = Kantor Pusat Pontianak | **Keamanan Kritis** |
| **AUTH-04** | Proteksi Cross-Branch Admin | `admin` (Cabang Sambas) | Mengirim request `POST /api/v1/visits/{id}/approve` pada kunjungan Kantor Pusat Pontianak | Ditolak oleh backend (HTTP 403 Forbidden) dengan pesan "Tidak berhak mengelola kunjungan cabang lain" | **Keamanan Kritis** |
| **AUTH-05** | Akses Global Super Admin | `super_admin` | Mengakses endpoint `GET /api/v1/visits` tanpa query param dan dengan `?location_id=...` | Mengembalikan seluruh data nasional jika tanpa filter, atau data cabang tertentu jika berfilter | Positif |
| **AUTH-06** | Isolasi Data Vendor | `vendor` (Dimas Prasetyo) | Mengakses endpoint `GET /api/v1/visits` | Hanya melihat permohonan kunjungan miliknya (`pic_user_id = user.id`), dilarang melihat vendor lain | **Keamanan Kritis** |
| **AUTH-07** | Kelola Satpam Cabang | `admin` (Kantor Pusat Pontianak) | Mendaftarkan akun satpam baru di endpoint `POST /api/v1/users/security` | Akun satpam terbuat dengan `location_id` otomatis terkunci ke Kantor Pusat Pontianak | Positif |

## 2. MATRIKS PENGUJIAN FORM PENGAJUAN KUNJUNGAN (SCR-03) & STORAGE

| ID Uji | Modul / Fitur | Peran Pengguna | Langkah Pengujian | Hasil yang Diharapkan | Kategori |
|---|---|---|---|---|---|
| **VISIT-01** | Form Valid Lengkap | `vendor` / `admin` | Mengisi tanggal valid, tujuan kunjungan, data 2 teknisi, dan unggah PDF Surat Tugas 1.5 MB | Permohonan tersimpan berstatus `requested`, mengembalikan `visit_id` & HTTP 201 Created | Positif |
| **VISIT-02** | Upload File Berlebih (> 5 MB) | `vendor` / `admin` | Mengunggah file PDF/Gambar berukuran 6.2 MB | Ditolak oleh backend & divalidasi frontend (HTTP 400), pesan "Ukuran berkas maksimal 5 MB" | Negatif |
| **VISIT-03** | Upload Format Berbahaya | `vendor` / `admin` | Mengunggah file berformat `.exe`, `.sh`, atau `.zip` | Ditolak oleh backend validator MIME type (HTTP 400), hanya menerima `pdf`, `jpeg`, `png` | **Keamanan** |
| **VISIT-04** | Validasi Tanggal Terbalik | `vendor` / `admin` | Memilih `start_date` lebih lambat daripada `end_date` | Validasi Zod frontend memunculkan error, backend menolak HTTP 400 Bad Request | Negatif |
| **VISIT-05** | Multiple Visitors Valid | `vendor` | Menambahkan 3 pengunjung sekaligus dengan nomor KTP dan nama lengkap valid | Seluruh data teknisi tersimpan di tabel `VISITOR` terhubung ke `visit_id` yang sama | Positif |
| **VISIT-06** | Upload Foto KTP Teknisi | `vendor` | Mengunggah foto KTP pengunjung (JPG 800 KB) | Berkas tersimpan di MinIO bucket, URL tersimpan pada `visitor.id_card_photo_url` | Positif |
| **VISIT-07** | Akses Berkas via URL Bertanda Tangan | `admin` / `security` / `vendor` (pemilik) | Buka `GET /visits/{id}` lalu klik `assignment_letter_url` / `<img photo_url>`; ulangi dengan URL asing di DB | Berkas terbuka langsung (HTTP 200, tanpa 403 AccessDenied); URL asing tampil kosong, tidak bocor | **Keamanan** |
| **VISIT-08** | Nama Perusahaan Manual + Tujuan Bebas (di luar katalog) | `vendor` / `admin` | POST `/api/v1/visits` dengan `visitors[0].vendor_name` = "PT Subkon Mandiri" (tanpa `vendor_id`) dan `purpose_note` = "Perbaikan darurat" (tanpa `purpose_ids`); lalu buka `GET /visits/{id}` dan `GET /vendors` | HTTP 201 Created; `visitors[0].vendor_name` dan `purpose_note` tersimpan & tampil sama pada respons, `vendor_id` NULL; teks manual **tidak pernah** muncul di katalog/dropdown vendor maupun tujuan | Positif |
| **VISIT-09** | Aturan Minimal Tujuan & Batas Panjang Input Manual | `vendor` / `admin` | POST `/visits` 4x: (a) `visitors[0].vendor_name` 121 karakter, (b) `purpose_note` 201 karakter, (c) `purpose_ids` kosong **dan** `purpose_note` hanya spasi, (d) `vendor_name` valid **dan** `visitors[0].vendor_id` terisi | (a)(b)(c) ditolak HTTP 400 `VALIDATION_ERROR` dengan pesan Indonesia ("maksimal 120 karakter", "maksimal 200 karakter", "minimal salah satu") dan **tidak ada** data tersimpan — batas panjang dinilai apa adanya, tanpa exemptions bila `vendor_id` ikut terkirim. (d) HTTP 201: `vendor_id` menang, teks manual **tidak** tersimpan (`vendor_name_override` NULL) dan `vendor_name` tampil memakai nama katalog | Negatif |
| **VISIT-10** | Kunjungan Berhimpitan Ganda (Concurrent) | `vendor` | Mengajukan 2 permohonan dengan jadwal tumpang tindih selagi kunjungan pertama belum selesai | Kedua permohonan tersimpan berstatus `requested` (HTTP 201 Created); penilaian duplikat tetap keputusan admin pada approval (boleh menolak sebagai duplikat) | Positif |

## 4. MATRIKS PENGUJIAN OPERASIONAL CHECK-IN / CHECK-OUT (SCR-05)

| ID Uji | Modul / Fitur | Peran Pengguna | Langkah Pengujian | Hasil yang Diharapkan | Kategori |
|---|---|---|---|---|---|
| **GATE-01** | Check-in Tepat Waktu (Kamera) | `security` | Scan QR code kunjungan `approved` menggunakan kamera pos pada rentang waktu valid | Check-in sukses (HTTP 200), status tiket menjadi `visiting`, badge "Sedang di Lokasi" bertambah | Positif |
| **GATE-02** | Check-in oleh Admin Cabang (Dual-Role) | `admin` (Cabang sama) | Eksekusi check-in melalui tombol manual/scanner saat satpam patroli | Check-in sukses dicatat dengan `checked_in_by = admin_user_id` | Positif |
| **GATE-03** | Toleransi Awal (Check-in 1.5 Jam Sebelum Mulai) | `security` | Teknisi tiba 90 menit sebelum jadwal `start_date` | Check-in sukses karena masih dalam batas toleransi 2 jam (`start_date - 2 jam`) | Positif |
| **GATE-04** | Tolak Check-in Terlalu Dini (> 2 Jam) | `security` | Teknisi datang 3 jam lebih cepat dari `start_date` | Ditolak oleh backend (HTTP 400 Bad Request): "Kunjungan belum dibuka atau sudah melewati batas waktu toleransi." | Negatif |
| **GATE-05** | Tolak Check-in Kadaluarsa (> 2 Jam Pasca Selesai) | `security` | Teknisi mencoba check-in 3 jam setelah `end_date` | Ditolak oleh backend (HTTP 400 Bad Request): "Kunjungan belum dibuka atau sudah melewati batas waktu toleransi." | Negatif |
| **GATE-06** | Scan File Gambar dari Galeri/Chat (Mode 2) | `security` / `admin` | Memilih file tangkapan layar (screenshot) QR code dari galeri HP | File didekode via `html5Qrcode.scanFile()`, data tamu tampil, verifikasi berhasil | **Kritis Mobile** |
| **GATE-07** | Input Manual Kode Tiket (Mode 3) | `security` | Mengetik kode tiket (contoh: `VST-6094332826`) jika kamera buram | Sistem mencari ID tiket dan menampilkan detail tamu untuk verifikasi identitas fisik | Fallback |
| **GATE-08** | Tolak Check-in di Lokasi Salah | `security` (POP Mempawah) | Scan QR tiket kunjungan yang tujuannya ke Kantor Pusat Pontianak | Ditolak sistem: "Kunjungan ini ditujukan untuk lokasi Kantor Pusat Pontianak, bukan POP Mempawah" | **Keamanan Kritis** |
| **GATE-09** | Eksekusi Check-out Berhasil | `security` / `admin` | Klik tombol "Check-out" saat teknisi menyelesaikan pekerjaan | Status menjadi `completed`, waktu selesai dicatat, log total durasi kerja dihitung otomatis | Positif |
| **GATE-10** | Bypass Check-in/out Superadmin Lintas Cabang (Darurat) | `super_admin` | Scan QR / eksekusi check-in lalu check-out kunjungan cabang mana pun tanpa `location_id` | Check-in/out sukses lintas cabang (HTTP 200), tercatat dengan `checked_in_by`/`checked_out_by = superadmin_user_id`; penjaga status & jendela waktu tetap berlaku | Positif |
| **T1** | Klik Foto Selfie → Pratinjau Besar | `vendor` (SCR-04) / `security` / `admin` | Buka detail kunjungan (kartu QR vendor) maupun modal hasil pindaian di `/gate`, lalu klik/ketuk foto selfie salah satu teknisi | Pratinjau besar (large preview) foto selfie terbuka utuh di atas layar, caption "Foto selfie" tetap terbaca, dan menutup pratinjau mengembalikan tampilan ke posisi semula | Positif |
| **T2** | Pindai Beruntun Tanpa Refresh + Konfirmasi Gagal | `security` / `admin` | Di `/gate`: (a) scan QR check-in, konfirmasi, lalu langsung scan QR berikutnya **dan QR yang sama** untuk check-out tanpa memuat ulang halaman; (b) ulangi dengan konfirmasi yang digagalkan (mis. koneksi terputus saat proses) | (a) Semua pindaian berikutnya langsung terbaca (tidak perlu refresh), check-out QR sama berhasil tepat sesudah check-in; (b) modal **tetap terbuka**, pesan galat berbahasa Indonesia tampil di dalam modal (`role="alert"`), tombol "Tutup" nonaktif hanya selama proses berjalan lalu aktif kembali untuk menutup/mengulang | Positif |
| **T3** | Alur Approve → QR → Check-in → Check-out Otomatis | `admin` / `security` / `vendor` | Sebagai `admin` setujui izin; sebagai `vendor` buka SCR-04 hingga QR Code muncul; check-in lalu check-out lewat `/gate`; amati detail kunjungan (panel "Riwayat Status") tanpa memuat ulang halaman | QR Code muncul otomatis setelah approve; status berubah `approved → visiting → completed`; panel "Riwayat Status" menyegarkan diri dan menampilkan stempel Masuk/Keluar terbaru tanpa reload manual | Positif |
