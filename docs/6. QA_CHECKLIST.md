# SKENARIO UJI & QA CHECKLIST (QA_CHECKLIST.md)
# Project: THC Visitor Management System (VMS) - ISP Edition
# Versi: 3.1.0 (September 2026 LTS Tech Stack)

Dokumen ini adalah matriks pengujian jaminan kualitas (*Quality Assurance Checklist*) untuk memvalidasi kepatuhan fungsionalitas, keamanan data multi-cabang (*branch data scoping*), toleransi waktu check-in, dan integrasi object storage pada THC-VMS.

---

## 1. MATRIKS PENGUJIAN OTENTIKASI & ISOLASI CABANG (RBAC)

| ID Uji | Modul / Fitur | Peran Pengguna | Langkah Pengujian | Hasil yang Diharapkan | Kategori |
|---|---|---|---|---|---|
| **AUTH-01** | Login Berhasil | Semua Role | Masukkan email & password terdaftar yang valid | Berhasil login, menerima token JWT (HTTP 200), diarahkan ke dashboard sesuai role | Positif |
| **AUTH-02** | Login Gagal (Kredensial Salah) | Semua Role | Masukkan email valid dengan password salah | Menolak login (HTTP 401 Unauthorized), pesan error "Kredensial tidak valid" | Negatif |
| **AUTH-03** | Isolasi Cabang Admin | `admin` (Cabang Surabaya) | Mengakses endpoint `GET /api/v1/visits` | Hanya mengembalikan daftar kunjungan berstatus `location_id` = Surabaya | **Keamanan Kritis** |
| **AUTH-04** | Proteksi Cross-Branch Admin | `admin` (Cabang Malang) | Mengirim request `POST /api/v1/visits/{id}/approve` pada kunjungan Cabang Surabaya | Ditolak oleh backend (HTTP 403 Forbidden) dengan pesan "Tidak berhak mengelola kunjungan cabang lain" | **Keamanan Kritis** |
| **AUTH-05** | Akses Global Super Admin | `super_admin` | Mengakses endpoint `GET /api/v1/visits` tanpa query param dan dengan `?location_id=...` | Mengembalikan seluruh data nasional jika tanpa filter, atau data cabang tertentu jika berfilter | Positif |
| **AUTH-06** | Isolasi Data PIC Vendor | `pic` (Dimas Prasetyo) | Mengakses endpoint `GET /api/v1/visits` | Hanya melihat permohonan kunjungan miliknya (`pic_user_id = user.id`), dilarang melihat vendor lain | **Keamanan Kritis** |
| **AUTH-07** | Kelola Satpam Cabang | `admin` (Cabang Surabaya) | Mendaftarkan akun satpam baru di endpoint `POST /api/v1/users/security` | Akun satpam terbuat dengan `location_id` otomatis terkunci ke Cabang Surabaya | Positif |

## 2. MATRIKS PENGUJIAN FORM PENGAJUAN KUNJUNGAN (SCR-03) & STORAGE

| ID Uji | Modul / Fitur | Peran Pengguna | Langkah Pengujian | Hasil yang Diharapkan | Kategori |
|---|---|---|---|---|---|
| **VISIT-01** | Form Valid Lengkap | `pic` / `admin` | Mengisi tanggal valid, tujuan kunjungan, data 2 teknisi, dan unggah PDF Surat Tugas 1.5 MB | Permohonan tersimpan berstatus `pending`, mengembalikan `visit_id` & HTTP 201 Created | Positif |
| **VISIT-02** | Upload File Berlebih (> 5 MB) | `pic` / `admin` | Mengunggah file PDF/Gambar berukuran 6.2 MB | Ditolak oleh backend & divalidasi frontend (HTTP 400), pesan "Ukuran berkas maksimal 5 MB" | Negatif |
| **VISIT-03** | Upload Format Berbahaya | `pic` / `admin` | Mengunggah file berformat `.exe`, `.sh`, atau `.zip` | Ditolak oleh backend validator MIME type (HTTP 400), hanya menerima `pdf`, `jpeg`, `png` | **Keamanan** |
| **VISIT-04** | Validasi Tanggal Terbalik | `pic` / `admin` | Memilih `start_date` lebih lambat daripada `end_date` | Validasi Zod frontend memunculkan error, backend menolak HTTP 400 Bad Request | Negatif |
| **VISIT-05** | Multiple Visitors Valid | `pic` | Menambahkan 3 pengunjung sekaligus dengan nomor KTP dan nama lengkap valid | Seluruh data teknisi tersimpan di tabel `VISITOR` terhubung ke `visit_id` yang sama | Positif |
| **VISIT-06** | Upload Foto KTP Teknisi | `pic` | Mengunggah foto KTP pengunjung (JPG 800 KB) | Berkas tersimpan di MinIO bucket, URL tersimpan pada `visitor.id_card_photo_url` | Positif |

## 3. MATRIKS PENGUJIAN PERSETUJUAN & RESCHEDULE (SCR-02)

| ID Uji | Modul / Fitur | Peran Pengguna | Langkah Pengujian | Hasil yang Diharapkan | Kategori |
|---|---|---|---|---|---|
| **APPR-01** | Approve Kunjungan | `admin` / `super_admin` | Klik "Setujui Izin" pada kunjungan berstatus `pending` | Status berubah jadi `approved`, QR Code aktif dihasilkan dan siap diakses PIC | Positif |
| **APPR-02** | Reject Kunjungan dengan Alasan | `admin` / `super_admin` | Klik "Tolak Izin" dan mengisi catatan alasan penolakan | Status berubah jadi `rejected`, alasan penolakan tersimpan di database dan tampil di PIC | Positif |
| **APPR-03** | Reschedule Tanggal Kunjungan | `admin` | Mengubah jadwal kunjungan ke tanggal baru | Status berubah jadi `rescheduled`, `start_date` dan `end_date` terupdate | Positif |
| **APPR-04** | Hak Akses Approve Dilarang untuk PIC | `pic` | Mencoba hit langsung endpoint `POST /api/v1/visits/{id}/approve` via Postman/curl | Ditolak oleh RBAC middleware (HTTP 403 Forbidden) | **Keamanan** |

## 4. MATRIKS PENGUJIAN OPERASIONAL CHECK-IN / CHECK-OUT (SCR-05)

| ID Uji | Modul / Fitur | Peran Pengguna | Langkah Pengujian | Hasil yang Diharapkan | Kategori |
|---|---|---|---|---|---|
| **GATE-01** | Check-in Tepat Waktu (Kamera) | `security` | Scan QR code kunjungan `approved` menggunakan kamera pos pada rentang waktu valid | Check-in sukses (HTTP 200), status tiket menjadi `checked_in`, badge "Sedang di Lokasi" bertambah | Positif |
| **GATE-02** | Check-in oleh Admin Cabang (Dual-Role) | `admin` (Cabang sama) | Eksekusi check-in melalui tombol manual/scanner saat satpam patroli | Check-in sukses dicatat dengan `checked_in_by = admin_user_id` | Positif |
| **GATE-03** | Toleransi Awal (Check-in 1.5 Jam Sebelum Mulai) | `security` | Teknisi tiba 90 menit sebelum jadwal `start_date` | Check-in sukses karena masih dalam batas toleransi 2 jam (`start_date - 2 jam`) | Positif |
| **GATE-04** | Tolak Check-in Terlalu Dini (> 2 Jam) | `security` | Teknisi datang 3 jam lebih cepat dari `start_date` | Ditolak oleh backend (HTTP 400 Bad Request): "Belum memasuki jadwal toleransi check-in" | Negatif |
| **GATE-05** | Tolak Check-in Kadaluarsa (> 2 Jam Pasca Selesai) | `security` | Teknisi mencoba check-in 3 jam setelah `end_date` | Ditolak oleh backend (HTTP 400 Bad Request): "Jadwal kunjungan telah kadaluarsa" | Negatif |
| **GATE-06** | Scan File Gambar dari Galeri/Chat (Mode 2) | `security` / `admin` | Memilih file tangkapan layar (screenshot) QR code dari galeri HP | File didekode via `html5Qrcode.scanFile()`, data tamu tampil, verifikasi berhasil | **Kritis Mobile** |
| **GATE-07** | Input Manual Kode Tiket (Mode 3) | `security` | Mengetik kode tiket (contoh: `VMS-2026-0925-01`) jika kamera buram | Sistem mencari ID tiket dan menampilkan detail tamu untuk verifikasi identitas fisik | Fallback |
| **GATE-08** | Tolak Check-in di Lokasi Salah | `security` (POP Sawojajar) | Scan QR tiket kunjungan yang tujuannya ke Kantor Surabaya | Ditolak sistem: "Kunjungan ini ditujukan untuk lokasi Kantor Surabaya, bukan POP Sawojajar" | **Keamanan Kritis** |
| **GATE-09** | Eksekusi Check-out Berhasil | `security` / `admin` | Klik tombol "Check-out" saat teknisi menyelesaikan pekerjaan | Status menjadi `checked_out`, waktu selesai dicatat, log total durasi kerja dihitung otomatis | Positif |

| ID Uji | Modul / Fitur | Pemicu (*Trigger*) | Kondisi Data | Hasil yang Diharapkan | Kategori |
