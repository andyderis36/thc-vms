HOLE-1 (dropdown "Fasilitas Tujuan" di SCR-03 masih menampilkan seluruh katalog lokasi nasional kepada `admin`/`security` cabang) ditutup di sisi frontend dengan arah (b): `VisitForm` memurnikan `locationOptions` memakai `user.location_id` sehingga `admin` dan `security` hanya melihat tepat satu opsi — cabangnya sendiri — sementara `super_admin` tetap melihat daftar nasional (lintas cabang) dan perilaku `vendor` tidak berubah; arah ini dipilih atas empat alasan ringkas: (1) blast-radius minimal — cukup satu komponen (`VisitForm.tsx`) plus satu spec yang tersentuh, dibanding alternatif penyempitan di backend yang menuntut perubahan handler + repository + query sqlc + kontrak `openapi.yaml` sekaligus; (2) stabilitas kontrak — `GET /locations` memang didesain global-by-design (lihat `hooks.ts:157`: "Master data bersifat global (bukan per cabang) — aman dipakai bersama semua pengguna") dan sudah dikonsumsi oleh konsol `super_admin` serta form `vendor`, sehingga mempersempitnya per-pemanggil di server berisiko memecah dua konsumen tersebut; (3) threat model — nama dan kota lokasi bukan PII dan isolasi kunjungan tetap ditegakkan di backend (read path ter-scope `WHERE location_id` dan write path melanggar tetap 403), jadi penyempitan dropdown hanya menghilangkan petunjuk UI, bukan menghasilkan kontrol keamanan baru; (4) reversibilitas — bila kelak audit menuntut pengetatan server-side, hardening `GET /locations?scope=mine` dapat menyusul tanpa membatalkan perubahan FE ini; residual risk: pemanggil API langsung (di luar UI) masih dapat mengenumerasi nama katalog lokasi karena endpoint tetap tidak ter-scope, dan ini diterima untuk MVP.
